# 掉落音频接收改进（2026-10-29）

本次保留 v7 的音频格式，改进接收器及生成器使用的同版解码自检。已有 Mod 不需要重新生成。代码尚未发布或安装；结果不代表近期 25、28、32 的现场问题已验证解决。

## 接收流程

1. 原有 18 kHz 同步检测定位包。同步分数只证明包存在，不再通过加权平均提高物品身份分数。
2. 将 19.6 kHz 签名解调为 127 个复数码片。迭代选择候选、联合拟合其幅度与相位，扣除其他物品的贡献，再判断每个身份。保留同时掉落能力，不采用全局只取第一名。
3. 身份须同时通过完整签名、前后两段相关性和两段相位一致性检查。完整签名门槛为 `max(用户阈值, 0.56)`，两段各至少 0.40，相位余弦至少 0.5。候选准入的 0.24 不是接受门槛。最终分数取同步、身份两者较低值，且不是概率。
4. 对高可信身份，在原始 PCM 上细化起点、拟合实际接收幅度和相位，消除该包后重新检测。每一份待消除的物理包都要独立通过带内相关检查，包括预期的第二份包。只在拟合副本中消除，不修改录音或游戏声音。
5. 保留额外一包历史，使跨录音块的强包仍可被消除。强包仍即时报告，不人为等待整段缓存。
6. 两包独立通过身份检查、且间距匹配协议时，携带 `repeated` 证据。低分初报可以随后升级为双包确认，地面存在门控只记一次。无需再等下一次地面动画播放；单个弱包保留原有等待确认行为。掉落 OCR 已移除；确认 #24–#33 后异步保存截图，截图成败不改变音频结论。

计算有界：同一时刻最多拟合 16 个身份，消除检测最多 8 轮；流式保留约两包历史。正常强包不必等待第二包。控制消息的 CRC 和场景、敌对处理保持现有行为。

## 验证及边界

新增回归覆盖：

- 全部 33 符文，44.1/48 kHz，两件同起点掉落相差 20 dB，66 组均识别出两件且无额外身份。
- 25/28/32 三件不同音量，在 0、9、36、177、960、2400 帧错位下叠加宽带噪声、4.7 kHz 音效和回声，以 997 帧流式输入。要求三种身份均有可确认的证据；允许一次低分初报和一次确认升级，禁止重复初报。
- 强同步头配随机负载、仅半段真实签名，不能确认掉落。
- 1000 组确定性随机复数码片，无虚构身份。
- 低分双包确认进入存在门控后仅记一次。
- 原有多掉落、重采样、回声、控制消息、流式边界等回归。

独立复制旧版解码器作对照：旧版在弱符文被强符文遮蔽、36 帧错位的 25/28/32、半段签名三个新增测试上失败；新版通过。不是仅改变测试预期。

本机三份历史录音总计约 166.5 秒。前两份约 57.7 秒没有 v7 符文，新旧均无符文输出；向这些背景加入已知符文的原有回归也通过。第三份含原有 22/23，不能当负样本：新旧流式回放均输出相同的 18 个符文包，无新增身份。这些包是播放证据，不是 18 次独立掉落。

本机 release 回放以每块 100 ms 输入，新版三份录音耗时约 0.44、0.76、2.66 秒，最大单块约 12 ms；旧版约 0.23、0.39、1.21 秒。增加历史和消除计算有成本，此次回放低于实时预算，但不是多账号满载基准。

最近 25/28/32 的实际误报、漏报没有标注录音，尚不能计算现场召回率或每小时误报率。加强身份门槛也可能拒绝严重损坏且只有一份可用的包；不得据有限回归宣称绝不漏报。游戏未播放、静音、引擎抢占或频段被彻底切掉，均不能由接收器恢复。

## 后续协议选择

暂不改变载波或强迫重做所有 Mod：当前可复现的问题已有接收端修复。若现场录音证实 19.6 kHz 标记遭到显著衰减，则用真实输出做频段扫测，再设计多频段分集、不同映射的重复签名和独立身份校验；需同时评估多物品并发、听感、延迟以及生成器/接收器协议版本迁移。只把频率调高不能保证抗干扰。

## 回放方法

独立音频项目已增加 `crates/d2r-audio-protocol/examples/replay.rs`：

```powershell
cargo run --release --manifest-path crates/d2r-audio-protocol/Cargo.toml --example replay -- recording.wav
```

输出 JSON，包括每个包的身份、分数、起点、双包证据以及总体/单块耗时。诊断事件列表是检测器输出，不自动视为人工真值。
