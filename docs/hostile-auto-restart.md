# 敌对自动重开

实现日期：2026-10-19。代码、独立加工产物和自动测试已验证；游戏内宣战音效的触发范围、后台双击 Esc 的实际重开结果尚待实测。

## 使用

1. 在 Mod 加工中选择“敌对自动重开”。自动包含“双击 Esc 下一局”，不需要选择场景、掉落识别或局内房间工具。
2. 用加工后的 Mod 重新启动监听游戏。所有执行目标都需要安装“双击 Esc 下一局”。
3. 在识别设置中选择唯一的监听目标，开启“敌对自动重开”。保持 Hub 运行，开启游戏声音和音效。
4. 触发范围默认“仅监听窗口”；选择“所有游戏窗口”后，对监听窗口以及 Hub 管理的运行实例发送双击 Esc，不启动未运行的账号，也不枚举无关外部游戏。

共用音频采集与监听目标，但不依赖完整识别开关。只打开本功能时仍采集该进程音频，不记录场景与掉落。其他窗口的敌对情况只有在监听窗口播放该提示音时才会触发。

## 加工与协议

- 独立功能组：`hostile_auto_restart`，r1；依赖 `esc_next_game` r4。
- CLI：`--features hostile-restart`，可与其他功能组合。
- 仅处理 `sounds.txt` 的 `cursor_hostile`、`cursor_hostile_hd_1/2/3`，保留原声并加入独立控制信号，输出到 `data/hd/global/sfx/d2rhub_hostile/`。
- 当前游戏包缺少旧版 `cursor/hostile.flac` 时，旧版条目回退到高清敌对原声；其余音效不修改。
- 协议沿用 v7 帧和 CRC，在原先未使用的控制类型 ID 1 编码 `Hostile`；Frontend 保持 ID 0，物品、区域编号不变。旧版解码器拒绝该新控制值。
- 可增补、重做；已加工敌对资源再次加工时保留，避免重复叠加信号。Hub 校验功能依赖、音效映射和资源存在性。

## 执行

只接受当前监听进程的信号。每次触发固定目标集合、按 PID 去重，分别验证目标实际启动 Mod 中的双击 Esc 模块。受管账号缺少实际启动快照时不执行，避免依据修改后的账号设置误判正在运行的 Mod。

各窗口独立执行，不抢前台，连续发送四次 Esc 按下/释放，间隔 150ms。检查进程创建时间和窗口身份；关闭功能或切换监听目标/执行范围后停止后续按键。一个目标失败不阻止其他目标。状态显示“已发送四次 Esc”，不将输入投递当作服务器已退出的证明。

15 秒冷却抑制协议重复包和连续宣战触发，不依赖地图入场信号解锁。不自动重试失败动作。结果写入 `HostileRestart` 日志，并通过 `hostile-restart-status` 显示在设置页。

## 验证与待测

已验证：独立 Mod 只包含敌对和双击 Esc 功能；Hub 完整产物校验通过；控制信号在 44.1/48kHz、跨采样块输入下正确解码；设置不隐式开启场景/掉落识别；冷却、加工依赖与现有自动测试通过。

仍需双人游戏测试：别人宣战、自己宣战、取消敌对、队员向第三人宣战是否复用该音效；聊天框/暂停菜单、后台和加载期间的双击 Esc 行为。当前语义是“检测到敌对提示音就触发”，不能据音效名称声称仅对被宣战生效。尚未修改用户游戏 Mod 或自动开启运行开关。
