# LiteHub 易用性增强方案

> 2026-09-28 决策更新：三个 Mod 改为直接维护并发布成品，已移除加工器内置生成配方和 Hub 生成接口。下文涉及生成器与配方的架构描述属于历史方案，不再作为实施依据。


日期：2026-09-28。状态：设计提案；已核对本地生成器和 JCY 源码，未实现、未进行游戏内验证。

## 目标与范围

在 LiteHub 日常游玩轻量方案上增加地图入口辨识、背包与仓库整理辅助、重点掉落提示、技能结束语音及特定地图方向提示。保持模块可独立关闭，不将这些默认设置扩展到 BoHub、NullHub。

“仓库格局、背包格局”暂按界面布局与分区理解：保留当前游戏版本的实际容量、页签、物品坐标及交互规则。若需要增加真实容量，应另立离线玩法方案，不能通过界面扩展假装获得额外格子。

## 已核对的实现依据

- LiteHub 对应生成器 `main` profile。Hub 的 `src-tauri/src/lightweight_mod.rs` 调用独立加工器、校验生成清单；资源页面负责下载更新。
- 实际生成代码在 `D:/pro/d2r-audio-mod/src/lightweight/bundled.rs`，加载 `resources/lightweight/b13/main.json.gz`。现有配方基于本机 CASC 读取原版资源，检查输入和输出摘要；不内嵌图片、粒子二进制素材。
- main 配方已经修改背包布局，且置空部分普通/lowend 装备槽位 sprite。新增 UI 必须检查并恢复依赖，否则新增控件可能没有底图。
- JCY 的 `file_operations.py` 给物品实体附加 `ENTITY_DROP_LIGHT`、`PF_BEACON_ITEMS` 等节点实现掉落提示。
- JCY 的 `states.txt` 为 `battleorders`、`battlecommand`、`shout` 等状态设置 `offsound`；控制器通过 `sounds.txt` 的文件映射开关提示音，资源包含 `battleorders_off.flac`。
- JCY 的高塔指引覆盖 `data/hd/env/preset/act1/crypt/crypt{e,n,s,w}warpprev.json`；憎恨囚牢指引覆盖 `data/hd/env/preset/act3/travincal/meph{e,n,s,w}warp.json`。控制器将后者明确标为第二层小站指引。

## 功能设计

| 模块 | 首版体验与默认值 | 实现方式与限制 |
| --- | --- | --- |
| 地图出入口光圈 | 默认开启低强度静态光圈；上下层增加不同方向图形，小站采用独立样式 | 按入口对象、roomtile 或 preset 建立资源白名单，复用原版特效。只有映射能够确定上下层语义时才区分，否则显示通用入口圈。仅加强已加载入口，不宣称显示未探索出口 |
| 仓库格局 | 默认清晰网格、原生页签；可选符文/宝石/底材整理参考背景 | 背景分区只是摆放参考，不具备自动分类或格子限制。保留材料页等版本特有页面；公式速查放折叠附页，避免覆盖物品和页签 |
| 背包格局 | 默认提高网格对比、装备区紧凑排列；可选护符区/拾取区参考分界 | 先保证拖放、快速转移、装备切换和原生魔盒入口。内嵌迷你魔盒作为后续独立选项，需验证转换按钮与物品格命中范围 |
| 重点物品光柱 | 默认 Vex（26号）及以上符文、钥匙、器官；中档符文、宝石、珠宝、护符和指定底材可选 | 按基础物品代码独立映射。地面状态保留细光柱，落地可选短闪光，拾取后消失。首版不承诺按暗金品质、孔数、无形或词缀精确筛选 |
| 技能结束语音 | 默认 BO；BC、Shout、能量护盾、神圣之盾等按需开启 | 优先使用状态 offsound → 独立 sounds 条目 → 短语音。BO 文案为“战斗体制结束”。状态消失也可能来自耗尽、解除等原因，因此产品名称使用“技能状态结束提示” |
| 特殊地图方向 | 默认高塔地牢与憎恨囚牢第二层小站；后续扩展 A2 墓穴、世界之石第二层 | 针对各朝向入口/小站预制块配置箭头旋转与偏移。文案为“推荐探索方向”，不承诺实时定位楼梯或最短路线；逐地图变体验证后再启用 |

视觉采用低饱和、细线、低频或无闪烁的统一风格。入口圈与物品柱通过形状区分，避免只依赖颜色；所有效果预留弱/标准两档，默认弱档以保持 LiteHub 的性能定位。

## 两个优先验证的技术问题

1. **技能提醒准确性。** 源码确认存在状态结束声音入口，但不能据此保证仅本角色触发，也不能保证重复施放刷新、队友覆盖、死亡、换场景和退出不会发声。用 BO 做最小样例验证这些情况；如果触发无法区分，明确标注实际行为或暂不默认开启。不要用固定秒数计时替代真实状态结束。纯 Mod 路径不承诺跨技能播报队列或全局去重；确有重叠问题时，再评估 Hub 接收事件后播报的独立增强方案。
2. **地面实体与音频加工叠加。** 现有声纹加工会克隆物品实体及 Flippy/Ground 状态机。光柱补丁必须进入最终实体，并保留 Flippy 音频、模型、图标、依赖及状态转换。关闭光柱不能删除声纹节点，重复加工不能重复挂载节点。

## 工程落地

独立加工器负责资源构建，Hub 负责选择方案、展示配置摘要、安装及回滚。建议在加工器 `src/lightweight/` 下增加模块化增强层，以六个 feature id 管理：`map_markers`、`stash_layout`、`inventory_layout`、`loot_beams`、`buff_end_audio`、`route_hints`。

构建顺序：读取对应版本原版资源 → 现有 main 轻量配方 → 布局/导航/声音/物品增强 → 可选声纹及房间工具加工 → 依赖和摘要校验 → 临时目录发布。增强资源加入保护清单，避免被轻量化规则再次置空。

JSON 按受控节点合并，数据表按稳定键和字段修改，不整文件覆盖 JCY 数据表。声音条目、实体和 UI 节点使用 LiteHub 独立命名；预先检测同字段冲突。文本/图形补丁可沿用 CASC 配方，原创语音需要扩展现有配方的资产输入能力，明确版本、校验和来源，不能假定当前规则已经支持。

生成清单保留现有 producer/profile/mode 等身份字段，新增增强配方版本、功能参数、原版输入摘要和资产摘要。增强后重新计算最终清单与完整性数据，并同步调整 Hub 校验、资源打包与更新保护规则。不能只在现有成品目录手工放文件，否则生成记录与实际内容不一致。

首版发布一个推荐配置的标准 LiteHub 成品；第二阶段在现有 Mod 管理入口增加“定制 LiteHub”：六组设置、默认值恢复、语音试听、配置摘要、重新生成。配置变更应用后提示重启游戏；已有加工成品继续遵循项目的更新保护和重新加工流程。

## 实施顺序与验收

1. **可行性样例：** 一个楼梯光圈、四朝向高塔/憎恨囚牢样例、一个符文光柱及 BO 结束音。记录资源依赖与实机现象，尤其是随机地图和状态刷新边界。
2. **导航与掉落版本：** 完成已验证地图白名单、重点物品映射、弱/标准效果及声纹兼容；未知变体不强行加箭头。
3. **布局与语音版本：** 完成仓库、背包、选定技能；扩充普通/lowend、分辨率与 UI 缩放验证。
4. **配置与分发：** Hub 接入定制项，完善清单、可重复构建、同名更新保护、回滚和使用说明。

验收包括：

- 高塔各层与四种朝向、憎恨囚牢二层小站各朝向，多随机种子采样；记录例外而非宣称箭头百分百准确。
- 仓库个人/共享/版本专有页面、背包拖放和快速转移、魔盒转换、装备切换，确认可见格与点击区域一致。
- 物品落地、已在地面、拾取、丢弃、同屏大量掉落；同时开启声纹后检测数量、图标与模型均正确。
- BO 自然结束、重施刷新、不同等级覆盖、队友施放、死亡、传送、切图、退房；记录听得到的对象和是否误报。
- 对实际支持的国服/国际服版本分别构建校验；1080p、1440p、4K 和普通/lowend 资源路径验证。经典画面与手柄单独验收，未经验证不宣称支持。
- 同一场景对比原 LiteHub 的帧时间、显存和加载时间；先采样基线再设门槛，增强效果不能明显破坏轻量目标。
- 运行相关生成器与 Hub 校验测试，并复用现有轻量 Mod 加工兼容回归；最终游戏内验收不能由文件检查替代。
