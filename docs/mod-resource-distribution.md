# 资源分发

当前发布入口见 [发布指南](release-workflow.md)，客户端协议与升级事务见 [双源更新协议](dual-source-updates.md)。这里仅描述资源归属和用户操作，不再维护第二套打包命令。

## 三种独立产物

| 产物 | 源码与版本 | 安装位置 |
| --- | --- | --- |
| Hub 安装器 | 本仓库；npm、Cargo、Tauri 版本一致 | 用户选择的 Hub 安装目录 |
| `d2r-audio-mod.exe` | 独立 d2r-audio-mod 仓库 | 本机受管工具目录，按版本与摘要隔离 |
| LiteHub / BoHub / NullHub | 已确认的成品目录；记录游戏数据版本与精确摘要 | 对应客户端的 `mods` 目录 |

加工器不随 Hub 安装器内置，不在 Hub 源码中提交 EXE。Hub 扩展功能管理运行服务，Mod 管理负责游戏内容，两者分别配置。

## 用户操作

1. 进入“设置 → Mod 管理 → 下载与更新”，选择国服或国际服。
2. 查看安装位置、兼容性、当前版本和下载大小，下载加工器或需要的成品。
3. 下载按配置使用 GitHub / Gitee，失败切源；导入本地文件也核对大小与 SHA-256。
4. 为账号选择成品并重启游戏。需要识别或跟房时，再为成品加工对应游戏功能。

未修改的受管 Mod 可校验后原位更新，保留旧目录备份；已加工、修改或来源不明的目录受到保护。“检查更新”会校验本地受管文件，安装命令在下载前也会检查，并在替换前再次确认。首次打开和自动轮询只读取轻量状态，不重复扫描全部内容。没有安装记录的旧版目录，需要与下载包比较后才能确认是否为原始内容。

任务可取消，临时文件不会被当作成功安装。离开页面后进度和结果保留在后台任务中；返回下载页仍可看到对应资源的失败或取消状态。具体异常恢复和兼容规则见双源更新协议。

## 维护规则

使用 `.\release.ps1 -Target mods` 准备成品，`-Target processor` 准备加工器；只准备不会上传。准备好的同一任务可以检查、发布或补传，不应为补传重新构建。

`npm run package:mod-resources` 是准备 Mod 的兼容别名，也走统一工作流。旧 `scripts/package-mod-resources.py` 已停用并提示新入口，不再生成缺少现行保护的 v1 包。

`resources/mod-resources-v1.json` 是旧客户端兼容快照，保留其语义；新发布使用 v2 通道。不要覆盖旧附件或同版本不同内容，不把资源 Release 提升为软件 latest。兼容范围与资源出处见 [资源目录说明](../resources/README.md)。
