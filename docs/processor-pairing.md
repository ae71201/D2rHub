# Hub 与加工器配套互认

Hub 发起的加工、增补、升级、MPQ 转换和恢复必须通过双向校验。

- Hub 只使用当前有效资源清单指定且大小、SHA-256 校验通过的加工器，不再回退旧版或调试目录。
- 状态读取、安装提交前和加工前执行 `hub-compatibility`。加工器返回产品、实际版本、配套协议和所需 Hub 版本。任一缺失、不匹配、超时或失败均禁止加工。
- Hub 为子进程设置 `D2RHUB_VERSION` 和 `D2RHUB_PROCESSING_CONTRACT`。加工器在分派命令前反向验证。旧 Hub 的 `--events` 调用没有身份，也会被拒绝。
- 加工前校验在创建输出和恢复替换事务之前完成。失败提示包含更新要求，下载页与加工页都不会再声称旧版“仍可使用”。

当前协议为 `d2rhub-processing-v1-r32`，加工器要求 Hub `0.9.111`。这是明确配套要求，不以“版本更高”推断兼容。Hub 发版变更时，必须同步审查加工器的 `src/hub_pairing.rs`；加工协议变更时同时更新两端协议标识并验证。

发布必须先构建含握手的新加工器，用目标 Hub 身份实测握手及拒绝路径，再按现有发布流程更新资源清单的版本、大小和 SHA-256。现有线上加工器不因版本号相同而自动获得互认能力；未更新发布资源前，新 Hub 会按要求拒绝旧二进制。不得伪造清单摘要或覆盖已发布版本来绕过校验。

加工器独立 GUI、普通非事件 CLI 仍可单独使用；`--events` 是 Hub 管理的调用入口，必须提供匹配身份。该握手用于兼容性校验，不是对本地恶意程序的安全认证。
