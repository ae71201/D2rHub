# 登录完成判据替换方案（已实施，待实机验证）

日期：2026-09-26。测试分支：`codex/test-login-readiness`。
用户已授权实施。运行逻辑已替换，实机结果待用户反馈；最新行为见 `d2r-token-readiness.md`。

## 对照依据

上游固定版本：`shupershuff/Diablo2RLoader@6e871d65402b15c1b96d30d7695ef3f66bac2fc0`。

- [写入 Token](https://github.com/shupershuff/Diablo2RLoader/blob/6e871d65402b15c1b96d30d7695ef3f66bac2fc0/D2Loader.ps1#L5035-L5056)：DPAPI 密文字节写入 HKCU 的 `Battle.net\Launch Options\OSI\WEB_TOKEN`。
- [等待下一实例](https://github.com/shupershuff/Diablo2RLoader/blob/6e871d65402b15c1b96d30d7695ef3f66bac2fc0/D2Loader.ps1#L5365-L5382)：游戏启动、互斥句柄处理和窗口处理后读取基线，每约 451ms 比较注册表值，发现一次差异就结束等待。注释描述启动时与角色选择界面的两次变化，但代码并不是从启动前累计等待两次变化。
- 该等待仅用于 Token（含强制 Token）路径。上游 Parameter 模式使用账号密码参数，并非 D2rHub 的战网客户端模式；不能把其行为当成战网模式已验证的证据。
- 上游没有给这段等待添加超时、取消、进程退出检查，注册表变化也不带写入进程身份。

## 本地两种情况

入口：`src-tauri/src/commands/launch.rs`。

| 模式 | 当前游戏登录信号 | 继续队列条件 |
| --- | --- | --- |
| 战网 | ETW 目标 PID 成功查询 WEB_TOKEN，或连续两次 TCP 1119 ESTABLISHED | 登录信号及互斥清除；信号超时也可在原进程存活、互斥清除时降级继续 |
| Token | 同上 | 登录信号及互斥清除；同样存在 60 秒超时降级继续 |

战网客户端前置准备还有进程数阈值等检查，这是启动游戏前的步骤，与游戏登录完成判据不同。

## 建议实施方案

1. 两种模式共用一个 WEB_TOKEN 值变化检测器，比较原始类型和完整字节，不解密、不打印值。
2. Token 模式在自身 Token 写入成功后、启动 D2R 之前建立基线，以本次成功写入的 REG_BINARY 原始字节为基准并开始采样，等待后续非空 REG_BINARY 值变化。自身注入不是成功信号；不等进程发现或互斥处理完成才取基线，以免漏掉快速登录时的变化。提前观察到的变化可以记录，但必须等目标进程身份、存活和互斥清除均确认后才放行。这是对上游采样时点的有意调整，变化与角色选择界面的对应关系仍需实机核验。
3. 战网模式保留客户端准备和 D2R 发现流程；在前置准备完成、首次发送游戏启动命令之前建立基线并开始采样，重发命令不重置基线。此前注册表恢复不计入变化。启动命令之后战网自身刷新可能触发，必须实机核验时序。
4. 每约 450ms 采样；经 2026-09-26 实测反馈，战网改为两次实际变化，Token 保持一次，相邻相同值不重复计数；统一放行条件：达到模式要求的变化次数、原游戏进程仍存活、该 PID 的互斥句柄已确认清除。满足后停止跳过动画按键并继续下一账号。
5. 保留取消、原进程身份核验和退出检查；沿用 60 秒等待上限，但超时/读取失败/进程退出/互斥清除失败一律停止队列。删除“未确认登录也继续”的降级路径。失败不主动关闭用户游戏。
6. 删除旧 ETW/TCP 登录判据、竞争判断、诊断逻辑及专用测试；清理无其他调用的 token_registry_trace 模块、ferrisetw 依赖与专用 TCP 探测函数。更新研究文档和相关测试。后续收尾已删除无调用方的 TCP IPC、权限及 login_unconfirmed 前后端分支；WEB_TOKEN 常量移至新注册表变化模块。
7. 不改战网客户端前置登录与认证快照流程、Token 保存格式、进程识别、窗口整理及启动取消机制。现有实例复用不计作一次新登录。

## 必须验证的边界

注册表是共享状态，无法单凭值变化证明写入者就是本次 D2R。已有实例或战网后台刷新可能造成误判；反过来，基线建立太晚可能漏掉角色选择界面的变化。Token 模式按用户纠正，在自身注入之后、游戏启动之前建立基线；不能将注入前后的差异算作登录成功。战网模式没有相同的直接注入步骤，采用首次发送游戏启动命令之前的基线。此后的变化可能包含战网客户端自身刷新，因此仍需用户验证是否提前放行。

实机记录模式、客户端版本、PID、基线时间、变化时间、互斥状态以及用户实际到达角色选择界面的时间；不记录 Token 值。先各做一次单账号观察，再验证国服/国际服、Token/战网及混合串行启动、已有实例、失效 Token、网络断开、快速启动和加速器环境。若战网后台刷新与角色选择无法区分，不能宣称该模式已支持可靠登录确认，需要回看观察结果调整方案。

自动测试覆盖：自身写入不触发、相同值不触发、不同有效值触发、进程发现或互斥清除之前观察到的有效变化不丢失且不提前放行、空值/缺失/读取错误不触发、进程退出不放行、互斥未清除不放行、超时与取消停止队列。真实游戏成功时序仍需实机验收，单元测试不能替代。
