# 仓库与产品整理 · 2026-09-28

## 目标与取舍

多账号运行是 D2RHub 的底座。识别统计、自动跟房等也可以独立成为用户的核心工作流。保留现有能力与数据兼容，以明确的产品边界组织界面和代码，避免把已有安全约束丢在重写过程中。

本轮主要覆盖设置、Mod、资源管理与发布链。以下结果不代表全部前后端模块都经过同等深度审查，也不代表整个产品已通过成熟软件的完整体验与实机验收。

三个对象分别承担不同责任：

| 对象 | 用户关心的问题 | 责任 |
| --- | --- | --- |
| 账号 | 用谁、在哪个客户端、如何启动？ | 认证、游戏版本、启动参数、窗口与画质 |
| Mod | 游戏加载什么？ | 每个游戏版本独立的已安装库、下载、加工、账号引用 |
| 扩展 | Hub 提供哪些辅助能力？ | 按需添加与设置，运行状态和依赖明确可见 |

## 实施方案

1. **先保证正确性**：补齐 Mod 文件操作互斥，修复跨版本参数传播和引用检查；为确定的缺陷补回归测试。
2. **收拢设置导航**：游戏、扩展、应用使用同一层导航；已添加扩展可以直接进入；移除“左侧入口 + 顶部重复页签”的双层结构。
3. **整理 Mod 工作流**：已安装库与获取资源有稳定入口；普通列表展示名称、能力、使用账号，启动参数与删除留在明确的详情操作内。尊重用户选定的国服/国际服，即使目录为空。
4. **整理仓库入口**：README 只承担产品介绍、下载、快速开始与贡献入口；版本历史单独保留；文档有索引，并明确当前方案与历史记录。
5. **整理发布与资源边界**：桌面应用、标准 Mod、独立加工器分别维护版本和来源；修复附件分页；阻止旧资源打包入口继续产出不兼容内容。
6. **验证实际行为**：运行前端逻辑/UI 测试、生产构建、Rust 回归、发布脚本测试与手册资源检查；在真实 React 组件的隔离预览中核查重构前后布局。

## 审查发现

- 设置导航在常见窄桌面窗口变成横向滚动条，Mod/扩展入口被挤到末尾；扩展页又增加第二条页签。
- Mod 列表直接暴露共享参数、加工、下载和自定义参数等多种概念，没有区分日常使用与维护。
- `ModCatalogManager` 根据目录是否为空反复覆盖用户选择的游戏版本，导致空目录无法被正常管理。
- Mod 参数更新和删除引用检查缺少一致的游戏版本与物理目录身份边界。
- 构建/资源安装和目录删除/功能修改使用不同的互斥边界，可能交错修改同一 Mod。
- README、说明书和开发文档中的版本、加工器分发方式与当前代码发生漂移；发布附件只读取第一页。
- 设置草稿曾与已提交全局配置共享状态，后台事件可以覆盖用户输入。现已建立独立编辑会话，保存只提交变更字段，失败和保存期间的新输入都会保留。
- Mod 加工状态曾附着在识别控制器，导航、扫描、生成和启用互相影响；显式账号失效、构建后改版和失败重试都缺少清晰边界。
- 初次识别准备可能要求先选一个加工成品，形成无法完成的前置条件；已配置开关也曾被当作服务运行状态。
- 资源页面可能保留旧安装目录与任务快照，导致已删除的 Mod 无法下载、监听失败后一直忙碌；主动取消也曾被显示为失败。
- 加工器异常输出可能提前结束调用而未回收子进程；持续输出会延迟取消检查。
- 发布准备缺少同一源码快照的自动检查证据，手册图中保留已经移除的导航及跟房操作。

## 验证边界

浏览器预览使用真实组件和隔离测试数据，不运行游戏、不访问真实账号、不执行真实 Mod 安装。Windows 游戏登录、实际音频捕获和安装器升级仍需要实机验收。截图与本次日志保存在被 Git 忽略的 `artifacts/review-2026-09-28/`。

## 本轮交付

| 工作 | 结果 |
| --- | --- |
| 设置导航 | 游戏 / 扩展 / 应用单层侧栏；已添加扩展可直接进入；键盘切换等待保存成功 |
| Mod 管理 | 已安装 / 下载与更新固定入口；按需展开单个 Mod 设置；空游戏版本不再跳回；独立加工工作流保留目标、来源、草稿与返回路径 |
| 加工恢复 | 取消仅作用于本账号的实际任务；构建成功后的应用失败保留结果；重试不重复生成或应用；执行及应用前重新核验账号与游戏版本 |
| 识别与跟房 | 识别单列布局，筛选和诊断按需展开；监听目标独立，不被主号替换；各入口只默认选择所需功能，组合明确选择，已有功能继承；状态依据后端实际运行结果 |
| 资源安装 | 主动检查及安装前完整性预检；保留本地修改；按资源恢复后台结果；取消与失败区分，任务监听失败不留下永久忙碌状态 |
| 扩展功能 | 完整列表呈现用途、添加状态、设置和移除；依赖影响在相关行和移除确认中说明 |
| 配置编辑 | 独立草稿会话；后台快照合并未编辑字段；失败保留草稿；关闭时若存在保存期间的新编辑则保持窗口打开 |
| 主界面 | 运行状态用文字加状态点表示；移除无法区分运行/空闲的 READY 标签 |
| 后端正确性 | 统一 Mod 变更与启动互斥；修复跨版本参数串改、目录引用检查、同物理目录别名及账号 ID 大小写匹配 |
| 后端分层 | 功能协议、参数、目录计划为纯模型；布局校验、生成器、文件操作、替换恢复和目录事务有独立模块；保留 IPC/配置及旧成品兼容 |
| 子进程 | 生成及版本探测共用管理器；处理错误、取消与超时等待退出；输出有大小上限；持续输出不会阻止取消 |
| 发布 | 附件分页；安装器绑定实际源码 SHA；源码快照内执行门禁并保存证据；补传核对证据及原始字节；旧任务兼容 |
| 仓库 | README / CHANGELOG / 文档索引分责；开发预览移到 dev；素材来源明确；统一编辑器与行尾约定 |
| 清理 | 删除未使用编辑器、旧加工弹窗、二级导航及重复加工表单；复用字段与样式按责任归位 |
| 构建目录 | 自动淘汰完整匹配 Tauri 模板的过时命令权限；自定义文件保留，增量构建不再重新引入旧 schema 条目 |

## 验证结果

- `npm run check`：TypeScript、全部既有逻辑测试、35 个 UI 测试文件（185 项）、36 项发布测试和手册检查通过。
- 前端生产构建、Windows x64 NSIS 构建通过；本地验证版本仍为 0.9.105，不代表正式 Release。
- `cargo test --locked`：544 通过、8 忽略、0 失败。
- `cargo clippy --all-targets --all-features -- -D warnings`、`cargo fmt --all --check`：通过。
- 手册：4 条路线、27 个步骤、9 张图片，源码版本和打包声明一致；新截图裁切与标注已检查。
- 一个已有的本地下载超时测试在并行运行时偶发失败，单项复跑及最终完整 Rust 测试均通过；本轮未修改下载实现。
- 未执行真实发布、账号操作、游戏内验证或安装器升级；原有工作区改动已保留在本轮变更中，源码提交以 Git 历史为准。
