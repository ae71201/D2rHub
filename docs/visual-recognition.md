# 视觉识别

场景及 TZ 由截图与 OCR 识别；声纹只保留掉落和敌对提示。新配置默认开启场景计时、低分掉落核验、地面名称持续可见及低分掉落确认过滤，核验阈值为 70%；已有明确保存的开关选择保留。配置通过
`ModuleConfigStore` 保存在 `%APPDATA%/D2RHub/modules/visual-recognition/config.json`。

## 使用

- 设置 → 自动跟房 → 房间与操作 → 拼房模式，或主页“跟房配置”快捷面板：默认使用原版创建／跟房且不发送、识别聊天信号；拼房主机只在创建前发送；拼房跟随只监听本机主号聊天并让主号及小号一起加入。三种模式互斥，共用同一份房间规则、账号和快捷键配置。
- 拼房跟随中，原创建快捷键也执行加入，不在本机建房。主号自动纳入加入队伍，不需要重复选为小号。切换模式会取消旧流程并更新信号会话；旧待触发信号不能越过模式切换执行。默认模式为旧配置迁移后的起点，旧视觉发送／监听开关不再决定运行行为。
- 设置页修改自动保存；快捷面板关闭、点击外部、按 Esc 或离开页面时自动保存模式和房间规则；无效输入或保存失败会提示，正常关闭时保留草稿供修正。规则复制／粘贴只同步房名和密码，不覆盖本机协作模式或账号。仅跟房共用窗口消息及共享 Ctrl 输入，无前台激活要求。
- 当前发送格式为 `+ + 501 + +`，数字与两侧加号之间也保留空格。默认每 2 秒检查聊天截图，从下往上逐行检测左右加号特征并 OCR；确认比去重记录更新的后缀后立即停止向上扫描。首次检查仅建立旧消息基线。后缀只用于去重，不比较或修改本机房号。新轮次触发后仅等待配置的跟房延迟，始终使用本机规则。两端须更新并自行复制／粘贴规则同步。
- 手动修改房名前缀、密码、起始序号或数字位数并成功保存后，会开启新的聊天去重会话；粘贴规则后成功保存也会重置，即使粘贴内容相同。快捷编辑离开时自动保存，设置页沿用自动保存。保存失败不会重置；普通开关监听、重启 Hub、系统自动递增房号不会重置。
- 重置同时取消旧的待跟房任务并清空 OCR 缓存；第一帧有效画面仍仅建立基线，不触发旧消息。如果重新从小序号开始，应先让旧的大序号消息离开识别区域，避免它再次成为基线。
- 已消费序号不会因消息消失或加载而重新触发。首次画面作为基线忽略；旧版、截断和格式不完整的信号忽略。详情见下方聊天 OCR 节奏。
- 设置 → 识别与统计 → 记录内容 → 场景计时与掉落核验：可启用每秒检查红字播报、驱动场景计时；低分掉落核验独立开关。截图目标跟随声纹进程，包括已选中的外部游戏实例。
- ROI 使用游戏客户区比例；提供一次性截图预览。最小化、黑帧、无法捕获均为“无法核验”。WGC 在系统支持的情况下可能显示捕获边框。
- 掉落默认核验并过滤未确认的低分事件；请保持游戏持续显示地面标签。关闭“只记录核验通过的低分掉落”可改用旁路核验。未匹配、无法核验和队列超时均不会计入已确认掉落；这可能漏记，可根据实际情况关闭确认过滤。

## 资源分发

安装包只包含 `resources/vision-resources-v1.json` 的小型版本清单，不包含 ONNX 模型、字典或 ONNX Runtime DLL；禁用 `ort` 的下载／复制 DLL 默认构建特性。模型内含字符字典元数据，无独立字典下载。

需要 OCR 的功能及其所属模块启动时检查线上清单、版本和 SHA-256；线上清单不可用、来源校验失败或接口不兼容时采用兼容缓存或随软件携带的固定版本清单。可在设置中“诊断与资源 → 重试资源准备”重新检查。仅发送聊天信号不需要 OCR；监听聊天信号现在需要按需下载并加载 OCR，以读取明文轮次后缀。

资源缓存为 `%APPDATA%/D2RHub/resources/vision/`，按内容摘要命名。下载有大小上限、SHA-256 校验、三次有限重试、临时文件、取消清理和原子切换；更新完成前保留旧资源。客户端遵循系统代理。文件损坏时重新下载或由已校验 ZIP 修复 DLL。清单只允许指定上游／项目发布仓库的 HTTPS 地址。

## 实现与限制

注册 `visual-recognition` capability，共享一个有界 worker 与 OCR session；CPU 推理限制 2 个内部线程。使用 Windows Graphics Capture 按需取帧，Rust 完成颜色特征、背景矩形和投影裁切；聊天保留原有行分割，不引入 OpenCV、Python 或通用文本检测模型。地区和掉落只 OCR 原始 RGB 裁片，不做二值化重试，也不对文字做连通域拆字或形态学操作。截图不上传、不常态落盘。

聊天先检查同一行的左右两对十字形：四个加号尺寸、基线近似，两对内部均有空格，且中间有容纳数字的间距，同时排除实心块；确认特征后才 OCR 读取数字后缀。地区启用后每秒检查配置 ROI 的红字形态，不依赖 TZ 或未知 Area 声纹触发截图；要求红字有文字行的高度、宽高比、密度及多处笔画分隔，再对原图裁片做 OCR。OCR 至少 0.90 分、有“进入／進入／Entering”前缀、去掉前缀后唯一匹配地区库才采纳。OCR 地区 ID 驱动分段：进入野外／地下城开始计时，换层结算上一分段并开始下一分段，回城结束计时。同一段连续播报不会重复重置；文字消失后再次进入同名地区可以开始新分段。计时采用实际经过时间，不再依赖音频帧数。地区匹配沿用 Mod 地区目录，只有内置目录时覆盖范围有限。

红字下方有紫字特征时，单独裁切原图 OCR，至少 0.90 分并精确匹配“恐惧区域／恐怖区域”及繁体或英文别名才标为 TZ。紫字稍晚出现只补充同一分段的 TZ 元数据，不重置起点或掉落；紫字淡出不撤销该分段的 TZ 状态。

主界面 OCR 按用户要求暂缓。直接退出到选人／大厅不会自动结束当前计时；下一次识别到场景或监控结束时才结算，可能包含菜单停留时间。场景识别关闭时没有自动切换及计时依据。

加工器整体配方 r26、音频功能组 r4，仅生成掉落／敌对声纹及完整 OCR 地区目录，不再生成地区、TZ、主界面声音。旧成品需从原始未加工来源重做；不能把含旧场景音的成品作为干净基线继续加工。OCR 模型及运行库仍按需下载。

低分掉落在现有音频去重之后提交核验；确认模式在视觉通过后才进入原入库路径。场景切换清除待核验事件，迟到结果不写入新场景。没有看到标签不能证明误报，界面区分“未匹配”和“不确定”。

识别条件：不同分辨率／字体／HDR 的捕获与分割、聊天消息可见性、后台遮挡及最小化、建房失败与输入焦点改变、简繁体标签别名、地面已有同名物品的歧义。颜色定位尚不能保证排除所有聊天、提示框和场景特效，掉落核验默认使用旁路模式，可根据实际画面选择是否启用强制确认。

## 验证

### 视觉诊断日志

在自动跟房的聊天信号设置或识别与统计的视觉设置中启用“诊断与资源 → 记录诊断日志”，开关自动保存并生效，成功后显示“已保存”。数值及截图范围在输入完成、离开输入框时自动保存；保存失败会明确提示，可点击“保存修改”重试，折叠重开保留当前草稿。默认关闭，旧配置自动兼容。可点击同区域的“打开日志目录”。

诊断内容写入现有 `%APPDATA%/D2RHub/logs/` 下本次运行的 `.log`，以 `[VisionDiagnostic]` 标记，后续内容为单行 JSON。日志沿用应用原有文件保留策略，不保存截图。

- `worker_start`／`worker_ready`／`worker_stop`：功能组合、ROI、轮询间隔、OCR 是否加载及资源准备耗时；失败输出 `resource_or_model_error`。
- `trace`：任务编号、类型 `chat/area/drop`、PID、总耗时、排队耗时及分阶段毫秒数。阶段包括截图、裁切、分割、二值化、OCR 或信号检测；次数和候选行数另记。总耗时从 worker 开始处理时计算，排队时间单独记录。
- 聊天日志记录 `ocr.decoded_tokens`（读到的轮次）、`dedup_token`（本次接受的轮次）、`dedup_watermark`（已消费最高轮次）、`local_sequence`（本机序号）、`baseline` 和 `trigger`；`dedup_persist` 是去重状态读写耗时。`chat_follow_dispatch` 只表示跟房入口是否接受，不代表服务器入房成功。
- 地区／掉落记录匹配、未匹配、不确定和错误，以及最多 8 个 OCR 文本／分数样本；每段文本截断到 160 个字符。记录声纹分数、预期掉落名称、确认／旁路模式；迟到或换图失效、队列拒绝和结果消费均有事件。未执行入库的旁路核验不会标为已确认掉落。
- 总计最多每分钟 120 条，达到上限后限流，下一次允许写入时用 `suppressed` 报告省略条数。诊断模式会增加少量计时和日志 I/O 开销，关闭后不输出视觉诊断记录；开启／关闭动作会记录一次状态切换。

常规 `cargo test --locked` 和前端测试不联网。显式原生 smoke test 会下载可选资源，验证校验、DLL 加载、模型字典、CTC 解码、单行文字识别：

```powershell
$env:D2RHUB_VISION_SMOKE_IMAGE = 'C:\path\signal.png' # 含 ++++ run-037 ++++ 的横向测试图片
cargo test --manifest-path src-tauri/Cargo.toml downloaded_model_smoke -- --ignored --nocapture
```

测试图只能验证该样本，不代表真实 D2R 识别精度或时延。

短聊天信号可单独验证加号检测、实际模型推理和后缀解析的完整路径：

```powershell
$env:D2RHUB_CHAT_OCR_SAMPLE = 'C:\path\chat.png' # 完整同一行 + + 501 + +
cargo test --manifest-path src-tauri/Cargo.toml native_compact_signal_smoke -- --ignored --nocapture
```

“地面物品名称持续可见”是用户确认项，表示截图能看见掉落名称。它不修改游戏设置、不模拟显示物品按键；未确认时跳过掉落视觉核验。


## 2026-10-19 排障修订

- 识别链路已移除在线 TZ 预报缓存读取、定时刷新与缓存补名。后续版本已完全移除场景／TZ 声纹识别，具体地点及 TZ 状态均来自视觉识别。独立 TZ 预报界面仍可查询预报，不参与识别命名。
- 原预览返回 data PNG，但应用 CSP 未允许 `data:` 图片。已仅对 `img-src` 添加 `data:`，并增加图片加载失败提示。预览同时展示原图、颜色掩膜和候选行；聊天预览展示各行匹配状态。
- 聊天日志增加 `line_analysis`：`glyph_runs`、`crosses`、`geometry_windows` 和 `reason`。当前原因包括 `too_few_crosses`（不足4个十字形）、`alignment_or_shape`（尺寸或同行排列不符）、`pair_spacing`（两侧加号对间距不符）。十字交点在字形中心区域搜索，允许抗锯齿或阴影造成的边界偏移。没有真实游戏信号裁片时，不能仅根据 `present=false` 确定是 ROI、颜色掩膜还是字体问题。

新配置的默认截图范围（左、上、宽、高）：地区 40%、20%、20%、9%；聊天 0%、40%、31%、40%。旧地区默认高度 4% 自动迁移为 9%，其他自定义范围保留。聊天接收与预览自动使用当前主号，旧的独立监听账号字段不再决定目标；目标或进程变化时清除待触发信号并重新建立基线。诊断日志默认关闭；仅改变诊断开关不重建 OCR 服务。

## 按需复用截图会话

截图使用 WGC 会话池，最多保留两个目标，15 秒无请求自动释放；窗口退出、最小化、尺寸或进程身份变化会淘汰旧会话，视觉服务停止时也会请求清理。支持最小更新间隔的系统会请求 100ms 的 OS 送帧下限；不支持时沿用系统行为。送帧不等于识别：无截图请求时不做 GPU→CPU 回读、RGB 转换或 OCR。

聊天和地区识别在 GPU 上裁切客户区后，只回读指定范围。CPU 直接按显存行跨度转换 RGB，省去整帧 RGBA 去填充复制和整帧 RGB 裁切。掉落核验仍请求完整客户区。客户区采用物理像素定位，不使用旧实现的标题栏高度猜测。每个请求只接受 QPC 帧时间不早于请求的画面，不保留旧图片作为超时回退。窗口边界变化或新帧超时会丢弃该次结果并淘汰会话。

诊断 trace 的 `capture_metrics` 区分 `reused`、排队 `queue_ms`、会话建立 `setup_ms`、等新帧 `wait_frame_ms`、GPU 回读 `readback_ms`、颜色转换 `convert_ms` 和总耗时 `total_ms`，并记录帧年龄及输入输出尺寸。`minimum_update_interval_ms=null` 表示系统未应用送帧间隔限制。没有实测前不承诺具体加速倍数；原 180～220ms 是旧实现全流程的测量。

可显式运行只读 A/B 基准，目标必须是非最小化的运行中 D2R 窗口，不会发送游戏按键或保存截图：

```powershell
$env:D2RHUB_CAPTURE_BENCH_PID = '实际游戏PID'
cargo test --manifest-path src-tauri/Cargo.toml compare_legacy_and_reused_gpu_roi_capture -- --ignored --nocapture
```

测试分别测量旧版完整截图＋CPU 裁切、新版首次截图和间隔 3 秒的会话复用，并确认闲置期间没有 CPU 回读。常规自动测试不访问真实游戏窗口。

去重只避免重复触发，不确认远端建房成功，也不修复两端规则失步。信号一经持久认领，执行失败或崩溃后不会自动重放同一轮次，可以人工跟房。

## 聊天 OCR 节奏（v3）

- 默认每3秒截图并做加号特征检测；无特征不进入 OCR。成功读到格式正确、平均分至少0.90的后缀后，全局聊天 OCR 冷却5秒，包括读到旧轮次的情况。冷却期间仍可截图和检测特征，但不推理。
- 最近32个成功的文字掩膜签名缓存在内存中；掩膜完全相同时复用已读轮次，不重复推理。签名覆盖两侧加号和数字所在的整行；持久去重仍决定是否触发。
- OCR 失败或未读到有效后缀时冷却2秒；每轮检查最多4次单行推理，优先最新候选行。读取成功后立即结束本轮 OCR。
- OCR 只识别通过双侧特征检测的行，并严格要求消息末尾为 `+ +数字+ +`（OCR 可省略空格）。不跨行拼接、不把其他聊天中的裸数字当轮次，也不猜测 O/0、I/1。
- 日志 `ocr` 字段记录 `ocr_calls`、`ocr_skip`（no_marker/cooldown/unchanged_mask）、`cooldown_remaining_ms`、`decoded_tokens` 和成功后的 `cooldown_ms`；OCR 耗时与截断样本沿用既有诊断格式。
- 预览按钮展示加号特征结果，自动监听才读取后缀，预览不执行跟房。首次有效画面仍只建立旧消息基线；新后缀与本机房号无关联。

## 2026-10-20 地区轮询与掉落标签核验

地区检查每秒最多提交一项，已有待处理项时不堆积；同一红色字形掩膜成功识别后复用名称，失败重试间隔 2 秒。换目标或场景清除识别上下文，迟到结果由音频侧 epoch 丢弃。特征只负责减少 OCR 调用，前缀和地区库唯一匹配负责防止误命名；未知／冲突不猜测。预览第二张图显示实际送入 OCR 的原图裁片，未发现红字时显示原截图及 0 候选。单 worker 忙于掉落时会顺延地区检查，不承诺严格实时；可见时间短于采样间隔的播报仍可能漏采。

低分掉落在声纹去重后进入队列。同一 PID、同一场景的请求合并 100ms 窗口，最多 8 项共用截图。先用蓝色背景比例／半透明黑底的暗像素比例、成对水平亮度边界与矩形稳定性找框；金边只辅助，不要求有金边。蓝底、黑底统一通过文字投影读取第一条完整名称行，排除细长装饰线、触边截断裁片；不拆字、不改原始字形。大于 1920 像素宽的图片在缩小图找框，名称始终从原分辨率裁切。

每帧最多 8 个候选，每批最多两帧、第二帧间隔 250ms、最多 12 次原图 OCR；1.5 秒为停止追加处理的软时限，已经开始的截图／推理不强制中断。OCR 至少 0.90 分才进入匹配，名称裁片 SHA-256 缓存最多 64 项，场景／PID 改变时清除，不保存截图。地区轮询与聊天检查均复用原有 worker 和按需下载资源，没有新增打包模型或原生图像依赖。

符文 `*玛尔 Mal#23` 提取完整中文、英文和 `#编号`；读出的字段必须指向同一个符文，只读到裸编号不确认。装备使用完整别名或一致的中英名称，不用任意子串或模糊相似度强行匹配。合成说明 `[x2+紫宝石]` 不参与匹配。每个声纹事件分别返回结果；某项成功不会阻止其他项继续核验，后续截图失败仍保留已确认项。强制确认模式只接收已匹配项，其余区分未匹配／不确定；旁路模式不改变原统计。

日志新增 `red_text_gate`、`feature`、地区 `ocr_skip`（no_red_text／unchanged_red_mask／retry_cooldown）；掉落记录 `batch_size`、`labels` 的背景类型与矩形、`label_detection`、`cache_hits`、`ocr_calls`、`budget_exhausted`、`unconfirmed_reason` 和逐事件 `drop_batch_result`。所有截图仍默认不保存。
